# 启动修复与配置变更范围

更新：2026-11-02。分支：`codex/gateway-startup-diagnostics`。

## 当前决定

根据用户最新要求，撤回本分支的 YAML 存储统一和自动迁移实现。主配置、MCP、权限、桌面外观、Computer Use、微信凭证、Gateway token、Web 数据库及浏览器偏好的现有路径、格式和读写接口恢复为 main。主配置解析器也恢复原实现，不引入启动时自动重写或新增字段白名单。原配置与凭证未用于迁移测试，验证使用临时目录。

原迁移方案同时触及多个功能的读写方、凭证来源和前端初始化，且曾在桌面联调中发现 Web bridge 的旧 token 读取遗漏。虽然该遗漏已修正，但这说明迁移必须作为独立工作组织，不能在多个功能并行开发时顺带完成。单独回退提交保留实验历史，便于以后检索，而不是重写 Git 历史。

## 本分支保留

- 启动错误分类、未知错误兜底、诊断 ID、退出 code/signal、stderr 摘要、日志路径和 Node 致命报告。
- Windows 进程身份查询及 Job 管理的原生缓存辅助程序；保留 PowerShell 回退和身份校验。
- 按需加载可选 IM/TUI 模块；关闭遥测时不读取队列或探测 Git；开启时限制历史队列大小。
- 编译后运行时的隔离启动基准：分别记录 Web、Gateway 和实际项目接口可用时间，同时校验旧配置字节不变。

共享小包 `@pilotdeck/config` 目前只提供运行时路径和诊断工具，不提供 YAML 读写、迁移或配置校验 API。原有启动入口文件位置保留，减少其他开发分支的合并冲突。

## 配置重构暂缓事项

不发布新的配置结构，不移动旧凭证，不把 localStorage 或 SQLite 迁入 YAML，不自动修复并覆盖用户配置。原先要求的统一存储、逐字段恢复和完整迁移验收属于后续独立工作，本分支不声称已经交付。

后续应先明确配置所有权和扩展约定、未知字段保留规则、版本化迁移接口、并发写入及兼容测试，再按一个功能一个迁移逐步推进。各功能在此之前继续沿用已有入口，避免开发者同时维护两套格式。

Gateway 架构判断及 Hermes、DSH 的官方依据见 [Gateway 架构评估](gateway-architecture-and-change-scope.zh.md)。
