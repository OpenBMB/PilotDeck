## 本次复现及修复

1. **队列图片发送重复，回答随之重复。** 网关队列确认使用 `text_<uuid>` 和 `queueItemId`，原逻辑只识别 `local_*` 用户回显。历史正文还附带文件路径说明，导致实时用户边界不能匹配历史记录。修复统一识别本地/队列初始输入，保存边界的队列身份，以本轮确认记录合并，并保留图片。中途 steer 不使用初始输入的合并键。
2. **状态事件截断思考匹配。** 历史接口中，后续轮次的状态事件可能位于前一轮正文之前。扫描现在跳过非对话状态事件，仍以真正的用户、工具、压缩和轮次边界限制匹配范围。
3. **完成后压缩标记移动到思考之前。** 分组代码在存在前文时不计算 `nextHost`，却用 `nextHost == null` 判断压缩是否位于结尾。修复检查压缩之后是否确实还有正文，并避免把压缩移到未完成的思考之前。

以上均补充了先失败、修复后通过的回归用例；第三项还增加了 DOM 排列测试。

## 压缩事件回放

打开 http://localhost:5173/e2e/fixtures/streaming-lifecycle.html?manual-reconcile 。

依次点击“回放实时消息”“合并滞后历史”“合并完整历史”；最后展开“Processed”和“Thought process”。
每阶段均应只有一份图片提问，内容顺序为：思考 → 压缩 → 回答。滞后历史携带较短思考和其他轮次状态事件，但暂不包含压缩记录。
修复前第三阶段展开后出现压缩在思考之前；修复后顺序保持。

此页面使用真实消息 store 与消息组件，仅在专用测试页面内拦截虚构会话 `s` 的历史读取；不修改真实会话。
真实模型会话仅使用约 11% 上下文，**本轮未触发真实自动压缩**，压缩验证属于事件回放和自动回归。
