# 交付开发可复制模板

配合[主操作手册](pilotdeck-staffdeck-delivery-sop.zh.md)使用。复制到项目文档后填写；未确定项显式标记，不留隐含决定。示例字段是项目记录格式，不是新增 PilotDeck API。

## 1. 基线与需求卡

```markdown
# 项目：<名称>
- 目标：<谁使用什么输入得到什么结果>
- 基线：<仓库、提交、实际 worktree、未提交增量说明>
- 环境：<Node/pnpm、安装与启动命令>
- 调用者与权限：<身份、业务资源归属>
- 输入：<格式、数量、材料版本、外部来源>
- 输出：<文件/结构化结果/业务动作及质量要求>
- 必做：<列表>
- 可选：<列表>
- 不做：<列表>
- 人工介入：<何时、谁、批准/拒绝/超时结果>
- 完成定义：<执行完成、流程完成、交付完成分别定义>
- 验收范围：<本地确定性/真实服务/生产级，各自必做项>
- 已确认假设：<内容、依据>
- 待确认决定：<问题、影响、负责人>
```

## 5. 可交给编码代理的 Goal 与执行 SOP

填写占位项后使用，不要将整本手册作为无限扩展授权。

```text
Goal：在 <绝对 worktree 路径> 基于 <可复现基线> 实现 <需求卡中的必做范围>，
完成 <验收编号与层级> 并形成可交接成果。<排除项> 不计入本轮目标。

执行：
1. 阅读需求卡、能力决策表、当前任务单及相关代码，确认目录与已有修改。
2. 按已批准的归属实现最小纵向增量。业务规则留在应用，数据源优先 MCP；
   精确生命周期和执行前阻断使用 Runtime 本地模块，不用远程 callback 替代。
3. 缺宿主能力时明确报告 capability unavailable；不使用空响应冒充实现。
4. 每完成一个增量运行最小相关验证并记录证据。协议/共享行为变化再扩大回归。
5. 不重写无关代码，不覆盖已有修改，不自动扩展到生产级评测。
6. 更新验收矩阵与交付说明，区分通过、失败、未执行、不适用。
7. 只有约定必做项全部满足且交付材料齐全才完成 Goal。
   遇到必需的外部凭据或业务决定，记录阻塞，同时继续独立可执行工作。
8. 提交、推送、发布按本次明确授权：<填写>。
```

| ID | 给定 | 当 | 则 | 证据层级 | 命令/记录/产物 | 结论 | 限制/负责人 |
|---|---|---|---|---|---|---|---|
| A-01 | 待填 | 待填 | 待填 | 本地/真实服务/生产 | 待填 | 未执行 | 待填 |

完成前逐项勾选：

- [ ] 必做场景通过；失败和未执行没有被汇总成通过。
- [ ] SDK capability、宿主配置和模块边界已说明。
- [ ] 交付产物已校验；执行成功与业务成功分开记录。
- [ ] 版本和未提交内容可定位，依赖与启动说明完整。
- [ ] 配置示例不含凭据；持久化目录与责任明确。
- [ ] 取消、故障排查、升级回退已覆盖本项目约定范围。
- [ ] 非本轮范围及外部服务限制已列出。
