# 连贯启动界面与运行日志验证

日期：2026-11-02。Windows x64，Node 22.23.2，Electron 调试实例。

## 最终行为

- 桌面原生加载页、Web HTML 首屏和 React 等待页使用同一品牌布局和阶段文案。进度对应实际启动阶段，正常启动不显示日志路径、堆栈或内部参数。
- 原生页面到 Web 页面通过预加载桥接读取最新阶段和进度，避免重新从头加载。配置检查、服务启动、Gateway 启动及进入工作区保持连续；重新启动开启新的进度。
- 启动失败才显示恢复面板：简短原因、稳定错误码、日志位置、重新启动、保存运行日志。配置错误另保留模型设置入口。未知原因继续显示通用进程错误，不根据退出 134 猜测为内存不足。
- 桌面保存按钮调用 Electron 系统另存为对话框。用户选择位置后导出一个 UTF-8 `.log` 文件，汇总保留的运行日志、渲染器日志、崩溃报告，并再次脱敏；取消保存不提示成功。Web 使用认证后的日志下载接口。
- 设置 → 高级 → 系统运行日志：默认一周，可选 1、3、7、30、90 天，设置成功后立即应用清理策略。

## 配置与日志生命周期

沿用现有 `pilotdeck.yaml`，只新增一项，不迁移原有 JSON、数据库、凭证或其他 YAML 字段：

```yaml
webui:
  runtime:
    logRetentionDays: 7
```

缺失、类型错误或不支持的数值单独回退到 7。现有配置的写入串行化、版本冲突检测、未知字段透传、掩码密钥恢复保持原实现。启动只读该设置，不自动重写文件；完整 YAML 语法错误仍显示可修复的配置错误界面。

日志仍位于已有位置：桌面为 Electron userData/logs，独立运行时为 PILOT_HOME/logs；PILOTDECK_LOG_PATH 覆盖保持有效。更新安装目录不改变用户配置位置。

`runtime.log`、`renderer.log` 按 UTC 日轮转，归档名包含日期和随机标识。保留天数包含当天，在启动、换日写入、每小时维护和设置变更时清理过期的受管理归档及崩溃报告；不删除不符合命名规则的用户文件或跟随目录链接。旧版连续日志文件首次跨日时整体归档，因此历史文件原有的较早内容会在该归档到期后整体清除。日志目录不可写时记录失败不会使运行时额外崩溃。

## 实机验证

全部使用临时复制的运行时、独立 PILOT_HOME 和 Electron userData，无真实模型请求。

| 场景 | 结果 |
| --- | --- |
| 慢阶段观察 | 仅测试副本中对 Web/Gateway 及 App 脚本响应各延迟 20 秒，用于观察原生、HTML、React 三段衔接；生产启动未增加等待 |
| 真实 Gateway OOM | 16 MiB 测试堆限制触发，界面显示可用内存不足、PD_RUNTIME_OUT_OF_MEMORY，隐藏原始堆栈 |
| Web 缺失模块 | 服务不可用时原生页面正确显示 PD_RESOURCE_NOT_FOUND，仍能调用系统保存对话框 |
| 恢复启动 | 还原测试副本的 Web 入口，点击重新启动进入工作区，Gateway ready |
| YAML 语法损坏 | 显示 PD_CONFIG_INVALID、日志位置及模型设置入口，错误配置文件字节不变 |
| 原生另存为 | 实际保存到指定中文文件名；48,598 字节导出文件包含诊断码、堆栈和崩溃报告，未出现测试密钥 |
| 取消保存 | 原生恢复页保存对话框可取消，页面继续可用 |
| 设置持久化 | 从界面选择一个月后，原 YAML 中保存 30；模型密钥和 MCP 文件保持完整 |
| 实时清理 | 经现有配置接口改为 1 天，桌面父进程立即删除过期测试归档，保留不相关用户文件；恢复为 30 后重新读取正确 |
| Web 日志下载 | 认证接口返回 200，内容包含本次故障证据 |

截图、日志和 JSON 验证证据在工作区 `artifacts/startup-progress-2026-11-02/`（不提交运行日志）。`html-handoff/` 为最终原生与 Gateway 进度截图，`oom/`、`web-module-missing/`、`config-invalid/` 为对应故障证据。Web 首屏的居中样式限定在 `#root`，避免嵌入 HTML 时受 body 布局影响。
