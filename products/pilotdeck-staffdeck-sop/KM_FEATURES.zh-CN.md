# KM 功能介绍

KM（Knowledge Management，知识管理）用来把分散的资料整理成可持续使用的知识：上传文档、保留来源、查找相关内容，并在回答或工作流程中引用依据。

例如，把报销制度放进知识库后，使用者可以询问“提交报销的期限是多少”，查看查到的内容，并打开引用核对原文。资料更新后，也可以管理版本，让使用者知道自己依据的是哪一份内容。

本文介绍独立 Knowledge Core 的功能及其在 PilotDeck 中的使用方式。安装配置见 [部署文档](DEPLOYMENT.zh-CN.md)。不同部署可以选择不同功能，页面和可执行操作以实际启用的模块与权限为准。

## 适合什么工作

| 场景 | KM 可以承担的工作 |
| --- | --- |
| 制度与操作手册 | 集中保存资料，按问题查找条款并核对来源 |
| 项目资料管理 | 按知识空间和知识库组织材料，供项目成员或 Agent 使用 |
| 企业研究与尽调 | 保存资料、检索证据、将来源交给报告或 SOP 节点 |
| 知识整理 | 把文档中的主题整理为 Wiki 条目，查看条目之间的关系 |
| 内容维护 | 修改文档、主题和片段，管理知识版本与变更 |

KM 主要管理已经提供的资料。它不是默认联网搜索引擎，也不会因为建了知识库就自动获得外部网站、业务系统或其他空间的访问权限。

## 从上传资料到查到依据

典型使用过程是：

1. 选择知识空间和知识库；在精简部署中，可以直接管理文档。
2. 上传资料，系统创建入库任务，解析文本并整理内容。
3. 等待任务成功，查看文档正文、主题和可检索片段。
4. 输入问题，选择检索方式或可用模型，取得相关资料。
5. 打开结果中的来源引用，核对原文，再用于回答或业务工作。

上传完成只表示文件已经提交，入库成功后资料才可用于正常检索。任务列表可以查看状态和错误，并支持取消任务。

## 资料如何组织

KM 中几个常见名称的含义如下：

| 名称 | 可以理解为 |
| --- | --- |
| 知识空间 | 划分访问和使用范围，例如一个项目的知识范围 |
| 知识库 | 一组相关资料，例如“报销制度”或“某企业尽调资料” |
| 文档 | 上传的原始材料及其解析后的正文 |
| 主题（Bucket） | 按内容整理出的主题单元 |
| 片段（Chunk） | 检索和引用时使用的具体文本片段 |
| Wiki / 概念 | 围绕一个主题整理的知识条目，可以关联其他条目和来源 |
| 版本 | 某一时点的知识内容快照 |

这些不是要求使用者手工填写的全部步骤。通常从上传和查询开始，需要精细维护时，再查看主题、片段、Wiki 或版本。

## 上传、解析与内容维护

内置解析支持文本、Markdown、HTML、PDF 和 DOCX。旧版 `.doc` 需要先转换为 `.docx`。PDF 内置解析主要提取已有文本，不能承诺扫描件和图片自动识别；额外 OCR 或其他格式取决于部署接入的解析能力。

有写权限时，可以维护文档正文、标题，以及主题、片段和 Wiki 内容。多人编辑时会检查内容版本，避免后提交的旧内容直接覆盖别人已经保存的修改。

可以先查看解析结果是否完整，再进行后续检索。尤其是复杂排版、扫描资料和表格，不能仅凭“上传成功”判断内容已正确理解。

## 查询与引用

KM 支持普通文本检索，也可以在已配置模型时使用模型辅助检索。查询可以限定在指定空间、知识库、文档或版本内，避免混用不同项目和时期的资料。

查询结果提供相关内容和来源引用。点击引用可以查看对应原文片段；Agent 也可以通过引用解析工具取得来源，用于核对和生成带依据的输出。

例如：

> 在“员工制度”知识库中查找差旅报销的提交期限，请给出来源。

可以先查看命中的条款，再打开引用确认上下文。引用帮助追溯系统使用了哪些资料，但不保证模型对资料的解释一定正确；涉及金额、日期和重要决策时，仍应核对原文。

没有模型或关闭模型辅助时，仍可使用普通文本检索。判断模型链路是否可用，应查看实际查询和模型结果，不能只看服务健康状态。

## Wiki 与关系图

启用概念模块后，可以围绕资料形成或维护 Wiki 条目，记录一个主题的说明、与其他主题的链接和来源。关系图将已有条目及链接展示出来，便于从一个概念找到相关内容。

例如，“报销期限”可以关联“差旅报销”和“票据要求”。使用者可以从主题阅读资料，而不必始终按文件名寻找。

这类关系来自已整理的内容和链接，不能当作自动完成的企业实体调查。条目和关系的质量仍取决于原始材料及后续维护。

需要交换结构化知识时，可以使用 OKF 知识包导入、导出和检查。OKF 可理解为包含条目、链接和引用的一种知识交换格式。

## 版本与知识复用

启用知识库和版本模块后，可以保存内容快照、复制版本、同步内容、发布知识版本或回退。历史快照保持不可直接修改，需要恢复到可编辑内容后再调整。

这适合制度修订、项目阶段归档等场景：保留“当时使用的资料”，同时继续维护新内容。查询也可以限定版本，帮助避免用新制度解释旧业务。

启用空间和绑定能力后，可以把知识库绑定到指定空间，并管理该空间中的可见性。空间绑定不会绕过服务权限，也不等于自动向所有用户公开资料。

这里的“发布版本”指知识内容的版本管理，与向外部系统创建业务对象是不同操作。

## 发现建议与外部发布

启用发现建议模块并配置模型时，系统可以在处理资料时生成待审建议。使用者可以查看依据、审核、拒绝或导出建议。是否产生建议取决于内容和模型结果，并不是每份资料都会产生。

审核建议只表示完成了审核，不会自动在外部系统创建工具、流程或其他业务对象。向外部系统发布需要单独启用发布模块，并接入对应的发布适配器。

当前 PilotDeck 的标准 SOP＋KM 部署默认关闭外部发布，不应把“建议已审核”理解为“业务对象已经创建”。

## 功能可以按需启用

基础能力包括文档、主题、片段、任务、检索和引用；其他能力按部署选择：

| 可选能力 | 用途 |
| --- | --- |
| 身份认证 | 区分读写权限和服务访问身份 |
| 知识空间 | 划分资料使用范围 |
| 知识库目录 | 组织和维护多组资料 |
| 版本管理 | 保存快照、同步、发布和回退知识版本 |
| Wiki / 概念 | 维护知识条目和链接 |
| 发现建议 | 生成并审核资料中的建议 |
| 外部发布 | 通过适配器把已审核内容送到目标系统 |

这些开关由部署人员配置，存在依赖关系，修改后需要重启服务。关闭功能后，对应操作不可用，不能据此判断资料丢失，也不应直接改配置来代替数据备份或迁移。

PilotDeck 标准组合启用认证、空间、目录、版本、概念和发现建议，关闭外部发布。独立 KM 的精简部署可以只保留基础能力。

## 在 PilotDeck 和 SOP 中使用

KM 自带独立页面，也可以嵌入 PilotDeck 的 Knowledge 页面。使用者在页面管理和查找资料，Agent 则通过已授权的知识工具查询并解析引用。

标准组合默认只给 Agent 开放查询和引用解析。页面有资料维护功能，不代表 Agent 可以自动修改或删除知识；增加管理工具需要明确配置和权限。

SOP 可以在某个步骤调用 KM。例如，先查询企业资料，再为每名股东调查提供依据，最终汇总成报告。SOP 负责执行步骤，KM 负责资料和出处；两者可以组合，也可以分别部署和使用。详见 [SOP 功能介绍](SOP_FEATURES.zh-CN.md)。

KM 服务拥有独立数据存储，不要求 StaffDeck 后端或用户数据库。登录关联、模型和解析可以通过宿主接入，也可以按独立部署方式配置。模型效果、资料覆盖范围和授权范围仍决定最终能回答哪些问题。
